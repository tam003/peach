# ADR-0115：来源数据按界面语言显示，不写回账本

- 状态：已采纳
- 日期：2026-10-28
- 相关：ADR-0038、ADR-0052、ADR-0100

## 背景

界面已有英语与越南语，来源数据却仍是中文与日文：标签投影到中文规范词表，出演者与厂牌是日文规范名，标题优先取日文官方标题。界面语言不是中文的用户读不懂这些字。

## 决策

来源数据的译名只在显示时替换，账本的真相字段、实体规范名、筛选参数、链接与 API 的 `tags`、`title` 等字段保持原值。

- **标签**：`catalog_rules` 的中文规范标签在短语包 `frontend/src/i18n/phrases/tags.ts` 里给英语与越南语显示名，页面整段替换。规范标签缺译名由测试拒绝。
- **出演者与厂牌**：`/api/entity/latin-names` 给出 `{规范名: 罗马字}`，罗马字取自来源别名与资料站 `romaji`。主界面在非中文语言下取一次，整段等于规范名的文字换成罗马字。
- **标题**：作品卡片与详情载荷带 `title_en`，取自已保存的 r18dev 来源快照（`<sources>/library-metadata/<番号>-r18dev.json`）里英文页的标题。界面语言不是中文时，`javPreferredTitle` 先用它；越南语没有来源译文，也显示英文标题。没有 r18dev 快照的作品照旧显示原标题。

r18dev 的英文标题多是机翻，所以只当显示名，不进 `catalog_title`，也不产生候选。

## 未采纳

- **把 javdb 切到英文页面**：解析器读的是 `?locale=zh` 下的面板字段名，`genre_taxonomy` 也收录了 javdb 的中文原词，切换会两边一起失效。
- **账本加译名列**：译名不是来源断言，写进账本就要为它设计来源归属、撤回与复核，换来的只是显示。
- **机器翻译标题**：要选定翻译服务、承担费用并把标题发到第三方。现阶段没有既有集成，留待单独决策。

## 后果

译名覆盖面取决于来源：无码、FC2 与没有 r18dev 快照的作品没有英文标题；没有罗马字别名的出演者显示规范名。整段替换只认完全相同的文字，拼进长句的标签、名字与标题不替换。搜索仍按原文与别名匹配。
